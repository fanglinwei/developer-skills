# 代理协作协议

仅主审在已获协作或独立复核授权、判断值得委派后读取。子代理由主审交接适用规则，不递归委派。基础证据标准、分类、权限和报告格式以 [主 Skill](../SKILL.md) 为准。

## 1. 判断收益与调用预算

主审先看改动和已有修改。能独立检查的多个范围、不同依据的深入判断或关键候选的独立反证，可以构成收益；缺材料、文件多或代理可用本身不构成理由。高度耦合时主审集中分析。用户明确要求的独立复核须满足，无法执行则说明阻塞。

- daily 默认 0 次委派；明确授权后按实际需要安排。deep 获授权且适合协作时按需调用，默认本次总调用上限 **3 次**。仅授权一项复核时不据此扩展分线。
- 用户明确给出的上限覆盖默认值。每次创建、重新委派或升级/备用接续都计入总调用；给已有代理发送新的执行任务也计一次，不靠复用名字绕过预算。普通事实补充不另计调用，但须保持原任务范围。
- 并发不超过当前宿主空闲容量、用户限制及可独立执行的任务数。预计需要复核时先预留额度，上限不是使用配额。
- 存在 agent-fit 时遵守其路由、快照、次数和故障规则；用户指定模型及其他适用限制继续生效。总预算与单任务限制同时满足，不在这里硬编码模型或 effort。
- 额度或能力不足时不继续新增调用。主审可继续其余工作；必需独立复核或覆盖未完成则准确披露，不把自查改称独立复核。停止状态未知的任务不交给另一代理重复执行。

完成条件：授权范围、职责、预计调用数和复核预留明确；派发前重核剩余预算与实际容量。

## 2. 选择职责并完整交接

只选择本次需要的职责，不固定代理阵容。职责定义调查方法，不设置严厉/宽松性格、问题配额或模型。共同准入、反证、分类、优先级、只读权限和最小修复要求只引用主 Skill，不在各模板复制。

### 公共任务契约

每次填写实际值，不只发送角色名：

| 字段 | 必要内容 |
| --- | --- |
| 目标与版本 | 模式、审查目标、基准、精确 diff/比较命令、适用提交列表；区分索引、工作区和相关未跟踪文件。 |
| 职责与范围 | 所选 A–D 模板、负责的入口/模块/判断维度、必要关联读取及排除范围。 |
| 权威依据 | 当前需求、验收、规范、接口约定；适用 Skill 的实际路径和需读取部分，无法访问时提供必要正文。 |
| 必要事实 | 带源码或配置来源的事实、假设和缺失材料；首轮不交接主审预判、其他线结论或置信度。 |
| 协作边界 | 其他线职责、共享接口和跨线流程的唯一负责人；范围限制责任，不禁止必要关联阅读。 |
| 验证限制 | 只读及工具权限、允许的最小现有检查、时间限制、剩余调用与复核预留；不递归委派。 |
| 完成要求 | 必查路径、停止条件、专项返回和未完成部分的披露方式。 |

主审保留跨线核实、共享裁决、根因去重及最终交付。发现范围外线索时返回主审，不自行扩大任务。事实已由主审核实不构成免检，接收者仍可重读来源并修正。

### 固定职责模板

**A：需求核对**

- 有可引用的需求或验收依据时启用。把分配范围内每条要求对应到实现与现有验证，检查遗漏、部分实现、实现偏差及有实际影响的范围扩张；核实来源版本和冲突。必要校验、错误处理或兼容工作不因未逐项列出而自动越界。
- 每条明确要求均有判断后完成；缺失或冲突依据只限制相应结论，不补造需求、不为缺少依据单独派发 A，其余审查继续。
- 专项证据：需求位置 → 实现/验证位置 → 符合性判断 → 支持或缺失的决定性事实。

**B：契约追踪**

- 改动影响参数、返回值、异常、副作用或状态转换时启用。追踪入口、调用方及必要下游，核对异步时序、旧调用方、默认值、格式、混合版本，以及失败/重试/取消/恢复与已有防护。
- 分配范围内受影响契约和关键调用路径均有判断后完成；无法读取或追踪的部分列为未完成，不因只分配实现职责而拒读必要需求或配置。
- 专项证据：变化的契约 → 实际实例与可达路径 → 成功/失败/清理或并发时序 → 实际结果 → 受影响调用方；按变化选取，不重复主 Skill 的检查清单。

**C：边界检查**

- 改动触及权限、隔离、持久化、一致性或资源控制时启用。明确主体、已有能力、输入和受保护资源；定位控制点与敏感操作，检查替代入口、批量、并发、存储写入、迁移、重试和恢复及已有保护。
- 指定边界的关键路径和防护均有判断后完成；决定性部署或运行事实未知时停止相应断言，列最小取证与结果分支，其余检查继续。缺少最佳实践不自动是漏洞，不扩为整库渗透测试。
- 专项证据：主体与能力 → 控制点 → 可达路径 → 资源与具体后果。

**D：独立复核**

- 有值得复核的候选、授权、剩余预算及未参与提出该候选的执行者时启用；候选提出者不能兼任。按第 4 节从当前源码主动推翻主张，核实关键前提、实际影响、最小修复必要性及相关路径完整性。
- 形成有据的成立、部分成立、不成立或缺少证据判断后完成；缺前提时报告限制，不用原作者自查替代独立复核，不声称完全盲审。
- 专项返回：判定 → 依据 → 修正意见或决定性缺失事实；不要求产生新的缺陷。

### 动态选择与统一返回

小修复可由主审承担 B；有明确规格的跨模块功能按需选 A+B；权限或数据变更按需选 C；关键或争议候选按需用 D。一人可承担多个职责，候选提出者不能承担该候选的 D。四模板不等于四个代理，默认总预算仍是 3 次，不为凑齐模板创建代理。

存储、迁移和恢复按契约/版本/时序归 B，按授权/隔离/持久化一致性归 C，主审指定交叉点负责人；必要时同一审查者承担 B+C，无需增加第五个默认模板。未委派维度由主审负责，包括适用的性能、资源释放、错误恢复和无障碍；角色列表不是全量检查清单。

共同返回：职责与目标版本 → 实际覆盖及依据 → 已确认缺陷 → 待确认 → 关键验证缺口 → 实际验证与未完成部分。发现采用主 Skill 的证据格式，空栏省略，可选建议按用户要求返回；专项证据嵌入对应项，不另写重复报告。D 返回专项判定，由主审映射证据状态。

完成条件：执行者知道查什么、何时返回及按什么门槛判断；主审对照目标核实所有实际覆盖和交叉路径，单个角色完成不等于整次审查完成。

## 3. 隔离判断上下文

需要独立判断且宿主支持时优先不继承父会话历史，例如 Codex 的 `fork_turns="none"`，由主审完整交接。宿主要求或用户指定继承时说明独立性的限制，不声称已经清除历史。

首轮共享版本、事实、标准，隔离主审预判及其他代理未经核实的发现、推理和置信度。经过核实且影响其他线的事实由主审同步；必要需求、权限模型和接口契约始终提供。交接缺事实时先补齐，不让代理猜测。

子代理通过工具返回结果，主审独占最终报告和共享状态；不读取其他代理草稿、不编辑目标源码或代理配置。必要临时输出按代理分目录，遵守主 Skill 检查限制，不接触其他目录、凭据或共享环境。对话继承控制和目录划分只是上下文/协作措施，不宣称是操作系统权限隔离。

审查期间主审记录版本变化，通知相关代理重核受影响证据。被变化推翻的旧结果不能直接进入当前报告。

## 4. 独立复核关键候选

分线不等于独立复核。获授权且预算允许时，为高影响、争议大或易误报的候选选择未参与发现的复核者；主审可以从预留额度中按需安排，简单且证据充分的问题无需逐条强制复核。

提供候选主张、准确位置、触发条件、必要证据、当前依据与规则，不提供其他复核者结论。要求从当前源码尝试推翻调用可达性、约定违反、防护无效和影响大小；能够安全执行时独立检查决定性结果。收到候选后属于针对主张的独立验证，不称完全盲审。

返回“成立 / 部分成立 / 不成立 / 缺少证据”与依据、修正意见。复核核心主张及用于支撑它的实例参数、旧行为对比和防护是否分别成立；推演最小修复是否覆盖相关失败与恢复路径。主审将结果映射到共同证据状态；保留成立部分、撤销被反证部分，缺事实则待确认。多代理赞同不能替代证据。

## 5. 主审整合

主审核实关键源码、版本和跨线契约，按根因去重并统一优先级。矛盾先调查，不能裁决时明确待确认，不拼接相反结论。核查实际覆盖与未完成部分，不能只接受“已完成”声明。

最终一份报告按主 Skill 输出，简述审查线、实际调用及覆盖限制；不输出完整代理对话，不重复各轴同根因发现。必需的独立性、覆盖或验证未满足时明确限制合入结论。
