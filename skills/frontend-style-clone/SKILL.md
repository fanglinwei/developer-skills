# 界面局部视觉复刻

在指定区域内尽可能 1:1 对齐参考，保留业务逻辑、接口、真实文案与数据、事件、状态绑定和无障碍。只调整样式及必要的局部结构，不引入全量 mock 或完整模块重建。仅分析时交付证据、差异和建议，不修改实现，也不执行实施专用步骤。

## 选择平台与协作技能

目标平台决定实现与验收，参考来源决定取证工具；只读取涉及的指引：

| 场景 | 指引 |
| --- | --- |
| 网页、浏览器应用、WebView 网页内容 | [Web](references/web.md) |
| iOS、Android、跨平台移动应用 | [移动端](references/mobile.md) |
| 桌面应用、原生宿主窗口、桌面屏幕取证 | [桌面端](references/desktop.md) |

例如 Electron 网页内容用 Web 指引，原生标题栏另用桌面指引；移动端以桌面应用为参考时，分别加载移动实现与桌面取证指引。其他界面沿用通用流程，按实际渲染环境适配，不强套 DOM/CSS。平台不明时先检查项目，仍不明再请求入口。

主文件负责通用流程；平台指引将视觉目标映射到各自的组件、布局、资源、动画与输入方式。实现及运行验证前，确认项目 UI 框架和版本，按当前工作加载匹配的可用技能，沿用现有技术栈，不预加载所有平台或开发技能。

按当前技能列表或安装目录解析协作技能，不写死路径、版本：有 Skill 工具则调用，否则读取 SKILL.md；已加载规则直接沿用。缺失时先查别名，仍缺失则说明受影响步骤，继续独立工作，不自动安装或假称执行。

- **Ponytail**：编码与对应审查时加载用户指定的本地或插件入口。遵从最新停用/级别指令，否则沿用当前级别，未启用时用技能默认规则；不按平台或子任务切档，不改持久配置，不将其解释为模型强度。它约束实现方式，不降低已确认的视觉、业务、无障碍和验收要求。
- **grill-me/grilling**：仅为无法从输入、项目或默认规则确定、且实质改变范围、参考或验收取舍的选择加载。入口转交或限制自动调用时使用其 grilling 实现并说明映射。每轮只问当前必要的 1–3 个简短问题，沿依赖顺序提供推荐，沿用已有答案；决定明确后直接继续，不追加开工确认。缺文件或入口只简短请求，等待时推进独立工作；依赖答案的修改待答复后进行。
- **agent-desktop**：需要桌面屏幕证据时，按桌面指引及该技能取证；网页调试仍用浏览器工具。

## 确定范围与视觉依据

先读项目约束，结合已有决定定位应用、窗口/页面/组件、目标区域、状态与允许修改项。信息足够就简述范围并开始，不重问事实或复刻档位；用户限定属性时只按该范围验收。

- 依据优先级：本次明确要求 → 指定截图、录屏或应用界面 → 参考网页或源码。截图描述静态状态，录屏描述变化；同级实质冲突需澄清，源码和工具读数不自动覆盖指定目标。
- 优先对齐参考视口、窗口或设备尺寸，其他尺寸沿用现有适配规则；记录主题、系统版本、字体缩放等外观条件。缺字体、图标或图片先查项目资源，仍缺失则说明影响并确认替代，继续不受影响部分。
- 复用项目封装、现有控件和已安装组件库，通过实际版本的公开配置、主题、布局与局部样式调整。显著差异受组件能力或无障碍要求限制时，说明依据并澄清取舍，不擅自替换组件。

## 定位与测量

定位视图、布局/样式来源、主题令牌、调用方及等效组件，按平台追踪实际生效规则、默认外观和浮层归属。修改共享项前核对影响范围，优先局部配置。

核对截图尺寸、裁剪原点、锚点和缩放，区分物理像素、屏幕坐标与平台布局单位；局部图不足以推断整屏尺寸。记录来源、条件及误差，区分工具实测、源码定义与视觉估计。可访问性文本和边界不能证明完整样式；工具或访问受限时列出证据缺口，继续已有材料支持的分析，不编造读数或声称完成取证。

录屏分析定位触发动作与变化的开始、中间、结束状态，按实际时间戳/帧率分别估计尺寸、位移、缩放、透明度、旋转的时长、延迟和缓动。操作等待、加载、滚动、导航与组件动画分别计量；不同属性可有不同节奏，不确定参数注明估计。

只记录实际差异的“当前值 → 目标值/依据”，不为未涉及项建清单：

| 类型 | 检查内容 |
| --- | --- |
| 文字 | 字体族及实际加载、字号、字重、颜色、行高、字距、对齐、换行、省略；先排除缺字体的度量差异。 |
| 控件 | 宽高、内边距、图标与间距、边框、圆角、背景、阴影；适用的悬停、焦点、选中、禁用、加载状态。 |
| 布局 | 容器、内外边距、间距、对齐、分隔线、滚动、尺寸适配；区分自然撑开与固定尺寸。 |
| 列表/表格 | 列宽、行高、表头、单元格留白、图文对齐、边框、斑马纹、操作列、空状态、分页位置；保留排序筛选分页逻辑。 |
| 弹层/素材 | 弹窗、抽屉、下拉层的尺寸、位置、留白、遮罩、层级；图片裁切、图标基线、素材比例。 |
| 动画 | 触发、起止、方向、时长、延迟、缓动、重复/反向、遮挡与布局变化。 |

## 局部实现

- 在已有布局和样式来源修正，先容器布局，再文字控件，最后装饰；避免堆叠覆盖。优先已有令牌，与明确目标不符时可用有依据的局部值。浮层使用项目支持的局部入口，避免影响其他实例。
- 只有样式无法完成目标时才改最小局部结构，保留语义、元素身份、绑定与状态。不要以隐藏真实内容、硬编码业务文本、整块截图替代界面或移除焦点状态凑图；固定测试数据使用已有测试设施，不改正式来源，不新增业务行为。
- 动画优先复用现有过渡与组件能力；必要时补最少的现有事件逻辑，还原触发和取消后的状态，清理计时器、监听器和平台动画资源，尊重减少动态效果设置。
- 安装依赖、启动长期服务器等遵循项目授权；任务不授予 Git 写操作权限。

## 验证与交付

1. 保存修改前基准截图；修改后等待字体/图片加载、动画稳定，在相同区域、显示条件、内容和状态下与参考对照。数据不同则区分内容与样式造成的尺寸变化，不改真实数据凑图；跨平台分别记录环境与系统渲染差异。
2. 先几何布局，再排版、颜色与细节，按需并排或叠图，修正后复查。录屏任务需在相同触发条件下本地录制或逐帧观察起中末的几何、有效透明度及各属性节奏，接受等效实现，不以写法或总时长代替可见效果；检查快速重复、取消、中途离开与减少动态效果。
3. 按平台回归受影响的交互、输入/焦点、无障碍、视觉状态、尺寸及共享实例。状态、事件或动画逻辑变化时，验证受影响的成功、取消、失败路径及资源清理。纯展示改动只验证展示，不新增业务操作链。
4. 运行已有且相关的格式、lint、类型、测试或构建检查；结构/逻辑变化按需补最小有效测试，不为纯样式新建框架。工具、素材、数据或权限不足时标明未验证维度；静态检查或构建通过不能替代视觉/动态验收。
5. 已确认条件与状态完成对照、主要可修复差异已消除且相关回归通过后交付；影响验收的剩余差异需确认取舍，轻微差异如实列出，不报告未测量的相似度百分比。简述平台与加载指引、修改文件、关键调整、实际 Ponytail 状态、测量依据、可用前后截图、检查结果及剩余差异。涉及组件选择时说明来源与依据，无需重复组件清单。仅分析时报告结论与计划，不把计划写成已验证。
6. 有仓库且修改了实现时展示 git status 与本次 diff 摘要，区分已有改动；停止于交付，不自动暂存、提交或推送。
