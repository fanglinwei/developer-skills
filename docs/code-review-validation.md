## 逐例规则推演

| 场景 | 判定 | 相对基线的检查结果 |
| --- | --- | --- |
| C01 上游限制 | 排除零分母主张 | 保留调用方和防护核实，显式主动反证。 |
| C02 数据库保证 | 排除重复 key 主张 | 补明框架/数据库保证，不能只看局部插入。 |
| C03 需求允许 | 排除行为回归主张 | 保留区分需求与推测，补当前需求依据。 |
| C04 未知 ingress | 待确认，不确认越权 | 保留缺证据纪律，补最小取证及两种结果。 |
| C05 无路径猜测 | 不进入待确认 | 明确待确认也有准入条件。 |
| C06 无关既有问题 | 排除 | 保留改动关联要求。 |
| C07 首次可达的旧路径 | 确认中优先级 | 保留“暴露”情形，明确未修改行可报告及归因位置。 |
| C08 租户越权 | 确认高优先级 | 保留真实安全缺陷发现要求；不能被降噪过滤。 |
| C09 保存丢失旧数据 | 确认高优先级 | 保留数据损失及恢复分支检查。 |
| C10 主流程契约破坏 | 确认高优先级 | 保留调用方核实，高来自实际主流程失效。 |
| C11 并发资金错误 | 确认高优先级 | 保留可达交错、真实后果和最小回归场景。 |
| C12 遗漏/部分实现 | 确认有限影响缺陷 | deep 原有需求核对保留，daily 补明确要求。 |
| C13 必要实现/额外外发 | 前者排除，后者确认 | 明确“未提及”不足以认定越界，依据禁止共享及实际路径判断。 |
| C14 旧 issue/无规格 | 当前要求优先，其余继续 | 补来源优先级与规格缺失的局部限制。 |
| C15 规范覆盖启发式 | 排除领域包装建议 | 保留项目风格与最小修复，补规则引用和规范分类。 |
| C16 未证实重试错误 | 关键验证缺口 | 从基线中优先级测试建议分离，禁止当已确认重复扣款。 |
| C17 已等效验证/仅缺文件 | 排除泛化补测试建议 | 用关键行为、漏检实现和等效验证约束。 |
| C18 可选导出的小错误 | 确认低优先级，仍报告 | 修正“功能错误一律高”及“低等于可选”的歧义。 |
| C19 低负载/函数长度 | 排除缓存和拆分要求 | 保留负载与 shortcut 纪律，补形态只是线索。 |
| C20 多路径同根因 | 合并但保留恢复路径 | 保留根因合并和最小完整修复，避免去重丢信息。 |
| C21 报告冲突/未覆盖 | 主审核实，限制合入结论 | 保留不拼接矛盾结果，补实际覆盖核对。 |
| C22 工作区变更 | 重核版本、位置和证据 | 明确目标一致性，不将索引或旧版本结果混入。 |
| C23 无授权/预算耗尽 | 不新增委派，披露限制 | 保留授权边界，新增累计预算与重试计数。 |
| C24 交接/上下文/复核 | 补事实，隔离预判，反证撤销 | 新增独立上下文及复核边界；不同目录不声称权限隔离。 |

推演结论：24 个场景均有明确的新规则处理路径；真实越权、数据损失、兼容性和并发缺陷的准入保留。该结论只覆盖规则文本可解释性，不证明模型实际执行效果。

## 受控模型对照的执行约定与限制

Q6 及 skill-creator 六项补充均已确认，执行约定以[完整改进计划第 11 项](code-review-improvement-plan.md#11-固定样例与对照评测)为准：分开发现与判别、分阶段比较规则/模板/协作、冻结完整依赖与执行条件、依据实际记录验收，并完成目标宿主验证和人类反馈闭环。本记录只报告已执行的事实，不重复定义整套协议。

在相同模型/effort、工具、适用项目规则与依赖 Skill 条件下，将基线和新规则放到不同干净上下文；使用相同任务，预期答案留在执行者不可访问的评分侧。记录实际输入和输出、可信模型元数据、错误分类、遗漏真实缺陷、重复及调用/耗时。随机化或互换顺序以降低顺序影响，必要时有限重复；缺失指标标未知，首次不承诺百分比。

首轮未建立独立模型运行，主会话的人工推演不冒充对照。用户确认实施范围后，本轮保存了改造前完整源码及实际使用依赖快照、补齐三个可执行最小工作区，运行下述有限诊断。历史 0.1.4 的完整环境仍未恢复，不能混用两个基线的结果。

Q6 的严格隔离与逐例独立/重复对照仍未完成；本轮结果不证明隔离收益或实际协作开销。不得用首轮表格的预期答案代替模型结果。
