## 对照方法

1. **分开发现与判别**：发现任务只给源码、diff 和必要依据，不提示候选或答案。评分材料须放在执行者不可访问的一侧；共享文件系统中仅要求不读取，不算强制隔离。
2. **分阶段比较**：先比规则，再比职责模板，最后比单代理与多代理；同轮避免同时改变规则、模型和代理数量后归因。实际协作仍需授权并遵守累计预算。
3. **冻结完整条件**：保存可恢复的 Skill、参考文件、实际依赖、项目规则及摘要；同一对比使用相同模型/effort、工具与必要权限，并保留可信宿主元数据。仅有主文件或请求参数不足以证明环境相同。
4. **独立执行**：版本间使用干净上下文；随机化或互换顺序，必要时有限重复。记录任务是否共用上下文、是否有保留任务、答案能否被访问；无法满足时标 PARTIAL。
5. **按行为评分**：运行前固定必需发现、可接受分类和硬约束。核对真实性、变更归因、优先级、遗漏、重复、修复完整性及实际工具记录；关键失败不被均分掩盖。规则推演、样例自检与模型输出分开计证。
6. **覆盖反证与执行边界**：包含有效防护、真实越权/数据损失、需求遗漏、已有问题归因、未知外部事实、等效验证、同根因恢复分支，以及无授权/预算、失败截断、目标中途变化和真实触发。具体输入和预期见上表，不复制成另一份清单。
7. **记录成本和限制**：记录可观察的端到端时间、调用与 token；缺失指标标未知，不将整组指标均摊为逐例测量或当作账单。无虚构证据、越权修改或超预算委派才满足硬约束。
8. **保留反馈和纠错**：每轮保存输入、版本、输出、逐项评分、工具记录与用户反馈，可使用 skill-creator 原有查看器。答案被反证时保留理由并按同口径重评；调优用过的任务不再称未见验收集。没有可证明的收益时停止迭代，不以文案或结构检查冒充效果。

历史实验产物在仓库旁的 `code-review-workspace/iteration-1/` 和 `code-review-eval/iteration-*`，未随源码或插件分发。本次文档整理未核验这些外部目录；下述数值是原记录摘要。

## 历史结果与限制

### 2026-10-28：0.1.5

规则、固定职责模板和三个可执行任务已实施；用户当日确认验收并要求发布。验收认可不补充未执行的测试证据。

- 24 个规则场景由同一主会话带预期答案推演，均有处理路径；只说明规则可解释性。
- 两个独立上下文各处理同样的三个发现任务：均排除受保护读取的越权主张，发现结算金额重复转换和归档导出遗漏，各为 6/6 内容判据。两版各组三任务共用上下文且只跑一轮；共享文件系统无强制答案隔离。评分由主代理完成，非独立盲评。
- 宿主记录两者均为 gpt-6.1-sol/high，输入与依赖摘要前后不变；未观察到修改源码、递归委派或读取评分材料。未观察到越界不等于无法越界。
- 协议决策练习 7/7、触发描述语义判断 8/8；没有实际创建审查子代理或验证自动加载。
