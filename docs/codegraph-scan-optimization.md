## 行为调整

- 从“每轮只同步一次”改成“每轮首次读取前维护；源码未变时复用，变更后下次读取前重新维护”。包括同轮编辑、文件增删/重命名、外部改动、工程/worktree 切换及压缩后无法确认状态。
- 保留提取版本升级的全量重建、维护后 JSON 健康检查、每工程每轮最多一次重建及故障回退；持锁和路径错配优先于重建建议。
- 无索引时遵守项目规则直接常规读取，不把普通检索变成强制启用访谈；仅明确要求启用时保留安装、交互 manual 初始化及权限边界。
- 合并重复触发、授权和汇报文字；正常维护不逐次汇报，异常及覆盖缺口仍需说明。

## Codex hooks 是否必要

本次不加入 hooks。Skill 足以描述按需维护流程；hooks 可降低漏调用概率，但不能独自保证所有项目读取都经过同步。若实际使用中仍反复漏同步，值得增加一个显式启用的查询前 hook，再以真实调用路径验收。

依据 [OpenAI 官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)：

| 事件 | 适合用途 | 对此目标的限制 |
| --- | --- | --- |
| `SessionStart` | 提醒索引维护规则 | 会话内后续改动不会重新触发同一启动事件 |
| `UserPromptSubmit` | 每轮提醒或状态失效 | 早于实际读取，也覆盖非代码任务；无法处理同轮后续编辑 |
| 同步 `PreToolUse` | 在受覆盖的代码查询/读取前完成维护 | 最贴近目标；须识别实际根目录、命令和工具参数 |
| `PostToolUse` | 编辑后标记状态失效 | 不能纠正已经读到的旧图谱，也看不到外部编辑器的改动 |
| `Stop` / 后台 hook | 提前维护或收尾 | 时机晚或不能阻止当前查询抢先运行 |

官方工具覆盖表说明：shell 与 `exec_command` 匹配为 `Bash`，`apply_patch` 可匹配 `apply_patch`/`Edit`/`Write`，MCP 使用实际 MCP 名称。matcher 匹配工具名，不直接匹配 shell 命令内容；`write_stdin` 不重新触发既有命令的 PreToolUse，一些特殊路径也可能不经过默认 hooks。单个 shell 命令中“改文件再查询”只能在命令整体运行前拦截，仍应拆开维护和查询。不要照搬其他宿主的 `Read`/`Grep` 工具名或宣称全覆盖。

未来若实现，先从 CodeGraph CLI/MCP 的查询入口做同步 PreToolUse，普通读取仍由 Skill 兜底。仅处理已有索引；按规范化根目录/worktree 隔离状态，对索引维护加互斥并复查，不能仅以 turn_id 缓存而忽略同轮或外部变更。排除维护命令，限制等待；失败返回明确上下文，让模型回退，不能把超时当同步成功。只在查询前维护，避免每次工具调用全量重建。

普通 hooks 需要用户审阅并信任确切定义，变更后重新审阅；不绕过 trust。配置可来自项目、用户或插件，多来源会合并、匹配 handlers 可并发执行，因此不能假设“装一个就替换旧的”。先检查重复配置与当前宿主支持。上述为设计评估，未部署或实测 hook。
